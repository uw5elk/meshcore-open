# MeshCore Open — український форк

Форк [zjs81/meshcore-open](https://github.com/zjs81/meshcore-open): Flutter-клієнта для радіомереж MeshCore (LoRa). Форк орієнтований на **роботу лише через радіо**, без інтернету: у ньому додані передача файлів і фото по радіоканалу, ефективне стиснення українського тексту та повністю переписана українська локалізація.

Усе, що не згадано тут, працює як в оригінальному застосунку. Загальна документація (англійською): [documentation/](documentation/README.md). Оригінальний проєкт: [zjs81/meshcore-open](https://github.com/zjs81/meshcore-open).

## Що відрізняється від оригіналу

| Можливість | Опис |
|---|---|
| Передача файлів | Будь-який файл до 128 КБ в ефірі (до 512 КБ до стиснення) у канал, з перевіркою CRC-32 і повторами втрачених пакетів |
| Фото зі стисненням | Фото автоматично зменшується до обраного розміру (5–80 КБ) і надсилається як звичайний JPEG |
| Стиснення тексту | `UaZip`: словник слів і код Хаффмана, економія до ~70% для українського тексту (поряд зі SMAZ) |
| Українська мова | Інтерфейс переписано: лаконічно, з технічними термінами англійською, без обрізання рядків |
| Лише en та uk | Інші мови інтерфейсу видалено |
| Поділитися каналом | Довгий тап на каналі → QR-код для швидкого додавання каналу на іншому пристрої |
| Без регіонів | Інтерфейс регіонів (flood scope) прибрано: повідомлення завжди йдуть без регіону |
| Без інтернет-функцій | Вимкнено мапу мережі, перегляд зображень за URL і GIF; прибрано рекламний банер |
| Менший APK | Збірка лише для `arm64-v8a` |

## Встановлення

APK збирає GitHub Actions (Flutter на самому телефоні зібрати неможливо).

1. Відкрийте репозиторій на GitHub → **Actions** → останній успішний запуск **Android APK**.
2. Завантажте артефакт `meshcore-open-apk`, розпакуйте й встановіть `app-release.apk`.
3. Дозвольте встановлення з невідомих джерел, якщо Android попросить.

> Усі, між ким передаються файли чи стиснений текст, мають користуватися **однаковою збіркою** форку. Старіші збірки не розпізнають нові формати повідомлень.

Вимоги до радіо: прошивка companion з кодом версії **11 або новішим**. Змінювати прошивку не потрібно.

## Передача файлів

Файл передається пакетами каналу (GRP_DATA, тип `0xF11E`). Усі, хто знає секрет каналу, отримують файл, тож використовуйте **приватний канал лише з одержувачем**.

### Надсилання

1. Відкрийте чат каналу → меню вкладень → **Надіслати файл по радіо**.
2. Виберіть файл. Якщо стиснення зменшує розмір (текст, журнали, CSV), файл стискається zlib автоматично; JPEG, ZIP і подібні йдуть без змін.
3. У вікні підтвердження видно розмір до та після стиснення, кількість пакетів і приблизний час.
4. Хід передачі видно в смузі над полем введення. Кнопка ✕ скасовує передачу, повний список відкривається в **Передачі файлів**.

Передача завершується як *Доставлено, перевірено*, коли одержувач підтвердив повну копію, або як *Помилка* після 12 раундів без підтвердження.

### Отримання

Вхідний файл з'являється в смузі каналу й у списку передач. Коли він повний і перевірений, натисніть **Зберегти**. Отримані файли зберігаються лише в пам'яті й зникають після перезапуску застосунку.

### Фото зі стисненням

Меню вкладень → **Надіслати фото (зі стисненням)**. Виберіть фото, потім розмір: 5, 10, 20, 40 або 80 КБ (біля кожного показано приблизний час). Застосунок підбирає найбільший розмір зображення, а далі найвищу якість JPEG, що вкладаються в бюджет, показує результат і надсилає звичайний `.jpg`. Одержувач отримує просто JPEG, який можна зберегти.

### Скільки це займає

Один пакет несе 157 байтів файлу. Файл 30 КБ при типових радіопараметрах — це хвилини, а обмеження duty cycle у вашому регіоні можуть розтягнути це значно довше. Репітери пересилають кожен пакет, що навантажує ефір усієї мережі, тож надсилайте якомога менші файли. Докладніше про протокол: [documentation/file-transfer.md](documentation/file-transfer.md).

## Поділитися каналом

Щоб додати свій канал на іншому пристрої:

1. У списку каналів довго натисніть на канал → **Поділитися каналом (QR)**.
2. На іншому пристрої відскануйте код у застосунку (сканер додавання каналу).

QR містить назву й секрет каналу (`meshcore://channel/add?name=…&secret=…`), тож хто його бачить, читає канал. Не показуйте код стороннім.

## Стиснення тексту

Довжина повідомлення обмежена приблизно 158 байтами, а кирилична літера в UTF-8 займає 2 байти. Тому в налаштуваннях каналу чи контакту є режими стиснення:

| Режим | Для чого | Економія |
|---|---|---|
| **Стиснення SMAZ** | Увімкніть для стиснення. Застосунок сам вибирає найкоротший формат із SMAZ, `u:` та `z:` | до ~70% для української |
| **Стиснення Cyr2Lat** | Замінює частину кириличних літер схожими латинськими (А→A, о→o …) | ~15% |

Режими взаємовиключні: вмикаючи один, застосунок вимикає інший.

### Як працює UaZip (`z:`)

- Текст ділиться на слова, числа, пробіли й розділові знаки.
- Слово зі словника (70 тис. найчастіших слів: українські, англійські, радіо- та IT-терміни) кодується інтервалом рангу та зсувом — приблизно 10–14 біт.
- Слова поза словником (імена, позивні) пишуться побуквенно кодом Хаффмана. Регістр передається типом токена, пробіл після слова об'єднується з ним.
- Бітовий потік перетворюється на друковані ASCII-символи (base94, 13 байтів на 16 символів) і йде як `z:<дані>`.

Одержувач розпізнає формат за префіксом, перемикати щось окремо не потрібно. Словник і таблиці є частиною формату, тож змінювати їх можна лише разом з новим префіксом. Еталонна реалізація та генератори лежать у [tools/ua_zip](tools/ua_zip/README.md).

## Локалізація

Доступні мови інтерфейсу: **англійська** і **українська**. Українські рядки лаконічні й технічні: терміни на кшталт flood, direct, advert, SNR, airtime, CLI, hex, PSK залишені англійською. Множина визначається за правилами української мови (`one/few/many/other`).

Файли локалізації: `lib/l10n/app_en.arb` (шаблон) і `lib/l10n/app_uk.arb`. Згенеровані файли `app_localizations*.dart` не зберігаються в git, їх створює `flutter gen-l10n` (його виконує CI). Локально перед збіркою запустіть:

```
flutter gen-l10n
```

Тест `test/screens/small_screen_layout_test.dart` перевіряє екрани на вузьких дисплеях (320 dp) і для `en`, і для `uk`, щоб рядки не перекривалися й не обрізалися.

## Вимкнені функції

У цьому форку вимкнено все, що потребує інтернету під час роботи:

- мапа мережі (надсилання зведень на `map.meshcoreopen.org`);
- завантаження зображень за посиланнями та GIF;
- рекламний банер на екрані сканера;
- інтерфейс регіонів: керування регіонами, вибір регіону каналу, рядок регіону в чаті, перемикач «Регіон поруч із кількістю хопів». Надсилання не змінює scope, тож усе йде без регіону (як за замовчуванням в оригіналі). Прийом повідомлень з регіоном працює як і раніше.

Мапа з кешем тайлів, переклад повідомлень і нейронні зображення залишилися доступними як опційні функції: вони вмикаються в налаштуваннях, а модель завантажується лише один раз.

## Збірка з вихідних кодів

```
flutter pub get
flutter gen-l10n
flutter build apk --release --target-platform android-arm64
```

Workflow CI: [.github/workflows/android-apk.yml](.github/workflows/android-apk.yml). Він завантажує Gradle з офіційного CDN (із запасними дзеркалами), кешує залежності, запускає аналіз і тести (їхні помилки не блокують збірку), збирає APK з повторами на випадок мережевих збоїв і завантажує артефакт `meshcore-open-apk`.

## Відомі обмеження

- Повідомлення каналів не мають підтвердження доставки на рівні MeshCore, тому підтвердження передачі файлу будується на власних службових пакетах (STATUS). При слабкому зв'язку воно може затримуватися.
- Передача іде **лише в канал**: у протоколі companion немає команди для бінарних даних у приватному повідомленні.
- Файли й фото вимагають однакової збірки в обох учасників.
